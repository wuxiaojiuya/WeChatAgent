# 微信文件通道

使用方法见 [助手模式](ASSISTANT_MODE.md)。为目标会话启用“微信文件收发”，聊天范围、管理员规则及 DSH 原生权限继续生效。

## 接收

微信 4.1.8.27 Hook 推送 appmsg-6 文件卡片 → 项目接收服务按连接、聊天和真实发送者登记引用 → 模型调用 `wechat_file_receive` → 用原消息下载字段调用 `/api/download_file` → 校验大小和摘要 → 复制到当前 DSH 工作区。

下载仅针对已登记的原消息，不扫描微信附件目录、不通过同名文件猜测来源，也不查询数据库。缺少回调、下载字段、授权或校验失败时明确报错，继续处理其他消息。

## 发送

`wechat_file_send` 核验工作区相对路径 → 暂存不可变副本并登记传输记录 → 后台队列调用 `/api/send_file_msg` → 根据 API 响应记录提交或最终确认。

普通成功码只说明接口接受请求；只有目标匹配、`baseResponse.ret=0` 且具有有效字符串 `newMsgId` 的原生回执才记为服务器确认。不扫描微信消息行等待回执，未知、超时或结果不完整的提交不会自动重发，也不把文件路径作为替代内容发给用户。

单文件上限为 50 MB。发送副本与记录在项目数据工作区的 `state/files/`；接收副本位于当前 DSH 工作区的 `.wechatagent-files/incoming/`，按项目连接、聊天、发起者和消息编号区分。文件内容不会自动执行。同一群共享其工作区，引用权限不替代 DSH 对工作区工具的权限。

当前唯一原生后端为项目内置的 **4.1.8.27 供应方 Hook**，不再使用旧 4.1.10.27 文件工厂或自编译 Hook。专用接口与验证范围见 [Hook 接入说明](SUPPLIER_HOOK_41827.md)。本次迁移的文件回归使用模拟 API 和项目缓存，没有自动向微信联系人发送文件。
