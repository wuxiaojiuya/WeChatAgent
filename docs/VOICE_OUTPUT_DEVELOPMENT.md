# 原生语音回复与指定音色翻唱：早期二开记录

当前实现请看 [肥鱼语音与本地 RVC 翻唱](FEIYU_MUSIC.md)。按用户后续要求，配置页已经改用肥鱼服务；本地分离＋RVC＋混音已经生成实际试听。肥鱼 HTTP TTS 服务仍需独立部署，API Key 由该服务生成，不使用旧火山凭据。

后续已按用户选择切换到 4.1.10.27，接入其提供的 WeChatVoice.dll，详见 [原生语音接入](WECHAT_NATIVE_VOICE.md)。本机已验证接口启动；真实聊天收发仍待登录后验收。`VOICE_INPUT.md` 只描述语音输入。TTS 检测通过不等同于推理或发送成功。

以下保留早期火山方案的探索记录，供追溯；其中的配置、测试数量及“尚未翻唱”等阶段描述不代表当前实现，不应继续按旧方案配置。

## 当前证据与版本选择

- `config/wechatagent.example.json` 默认微信版本为 **4.1.15.13**。先沿用项目默认版本；原生语音是否能在此版本实现，必须验证后才能确认。4.1.10.27 的文件发送实现不能直接套用到新版。
- `scripts/native-hook/text_4_1_15_13.cpp` 和 `scripts/native-hook/wechatagent_hook.cpp` 均未提供原生语音发送接口。添加 OneBot `record` 消息或把音频编码为 SILK 都不能替代此接口。
- 现有语音插件只处理收到的语音。API v2 的 `ctx.reply` 接受文字，也没有音频输出权限或动作，不能直接安装一个插件就完成目标。
- 项目已自带可编码与解码的 SILK WASM，无需另装编解码包。原生语音按单条不超过 60 秒设计；长歌曲将需要切片并验证顺序、回执及播放体验。

## 能力页面配置

控制台的“能力 → 能力目录”已添加 **语音回复**、**唱歌** 两个卡片，也可通过“语音与音乐”分类查看。不连接微信或 DSH 也能配置。

- 语音回复：可配置豆包语音合成/声音复刻、音色 ID、API Key、回复方式、开关和聊天范围。“保存并生成试听”将使用当前设置调用火山服务，生成可在页面播放器收听的 WAV，不向微信发送。
- 回复方式新增“由 AI 自然选择（推荐）”（`ai-choice`）：计划根据聊天语境、情绪和用户偏好选择文字或语音，长内容、代码或不方便听语音时优先文字。当前已支持选项展示和配置保存，实际 AI 决策仍需在回复与发送链路接通时实现；原有选择保持兼容。
- 情绪表达：支持随朗读文字自动表达、平静自然、开心、难过、生气、温柔安慰、担忧关切，以及轻微/自然/明显三档强度。自动模式由 TTS 根据本次文字表达，尚未接入完整聊天上下文。选择非平静模式时，通过 `req_params.additions` 的 JSON 字符串传递 `context_texts`，不会给朗读正文加情绪标签。
- Vivi 2.0、小何 2.0、云舟 2.0、小天 2.0 在官方音色表标注支持指令遵循。“精灵向导 2.0”（`ICL_uranus_zh_female_jinglingxiangdao_tob`）未明确标注该能力：使用语音合成 2.0 服务时尝试发送指令，页面提示效果待验证。声音复刻服务暂不发送情绪指令。试听响应返回是否已发送指令及支持情况，不把发送指令等同于情绪已生效。
- 唱歌：可保存 RVC、SVC 或自定义 API 的服务类型、地址、目标音色模型、变调、伴奏、分段时长、密钥和聊天范围。当前没有接入统一的翻唱请求协议，选择服务类型和保存地址不代表已经能调用该服务。
- 唱歌的音色来源默认“沿用语音回复音色”，共享角色身份。翻唱模型需显式关联到当前说话音色及资源；修改说话音色或资源后，旧关联不再作为可用模型返回，也不会把 TTS speaker ID 当作翻唱模型 ID。允许单独指定唱歌音色；旧配置中已填写的独立模型按此模式保留。该关联仅记录用户确认的对应关系，不表示已经验证听感一致或支持翻唱生成。
- 未选择微信聊天时可以先保存服务设置。页面显示“发送待接入”或“翻唱服务待接入”，不会把已保存配置标成已具备发送能力。
- 设置和密钥保存在本机 `state/voice-output/capabilities.json`，不进入 Git；配置查询和能力目录不返回密钥内容。密钥留空保留已有值，可勾选单独清除。
- `scripts/audio-capabilities.mjs` 提供保存、校验、脱敏、能力状态和试听接口；`public/console/audio-capabilities.js` / `.css` 提供配置界面。

相关测试：`npm.cmd run test:audio-capabilities`。覆盖配置持久化、密钥保留/清除、并发版本冲突、聊天范围、情绪指令协议与降级、唱歌音色跟随与旧配置迁移、试听与页面 API，并回归已有能力页面及 SILK 模块；全部 22 项通过。火山调用采用模拟响应，未产生真实调用费用。情绪音频效果仍需凭据实测。

## 已实现的独立模块

- `packages/voice-output/volcengine.mjs`：请求 24 kHz 单声道 PCM，解析跨网络分片的 JSON 音频包，限制长度与响应大小，处理超时和取消，不回显服务端错误正文或密钥。
- `packages/voice-output/prepare.mjs`：将 PCM 补齐最后一个 20 ms 帧后编码为 SILK，验证封装和 60 秒限制。
- `scripts/voice-output-smoke.mjs`：读取一个本地文本文件，生成本机 SILK 文件，始终返回 `sent:false`。不会连接微信或发送消息。音频写入 Git 忽略的 `state/voice-output/smoke/`。
- `scripts/test-voice-output.mjs`：模拟火山接口测试协议与失败处理，并用真实 WASM 编码、解码测试音频。测试不访问付费服务。

运行测试：

```powershell
npm.cmd run test:voice-output
```

开通语音合成且取得新控制台 API Key、音色 ID 后，在本机 PowerShell 设置环境变量，不把真实凭据写入源码或聊天：

```powershell
$env:VOLCENGINE_TTS_API_KEY = '<在本机填写>'
$env:VOLCENGINE_TTS_SPEAKER = '<控制台音色ID>'
$env:VOLCENGINE_TTS_RESOURCE_ID = 'seed-tts-2.0'
# 先在本机保存一份不超过 500 字符的 UTF-8 文本，例如 state/voice-test.txt。
npm.cmd run voice-output:smoke -- state/voice-test.txt
```

该命令会调用火山计费接口。输出超过 60 秒时本阶段返回失败，不截断或自动发出。还没有 API Key 时只运行离线测试即可。

## 后续实现顺序与验收

1. **先验证原生发送**：准备匹配的微信 4.1.15.13 客户端、上游 Hook 头文件、C++ 构建环境。研究该版本的语音消息构造和提交路径，添加真实的 `nativeVoiceSend` 能力检测以及本地发送接口。当前仓库没有现成接口，不能虚构函数偏移或复用文件发送。
2. **最小发送验收**：先用本机合成的短测试音频，确认微信对话中呈现语音条、手机可播放、时长与内容正确，且数据库出现新的 type 34 消息及有效服务端回执。真实发送需要用户指定测试会话。
3. **接回复链路**：扩展适配器、DSH 工具和设置页；复用白名单、独立持久队列、提交前记录、账号隔离和不确定提交不重复发送。火山错误只能说明生成失败，原生接受请求只能说明已提交，取得回执后才能标记已送达。
4. **再做翻唱**：确定具有保留旋律能力的 SVC 服务或本地模型，以及该后端专用的音色模型；TTS 的 speaker ID 不应假定能复用于歌声转换。输入原曲或人声、分离人声与伴奏、转换歌声、混音、切分不超过 60 秒的语音片段，依次发送并查询回执。先验证一段副歌，再扩展整曲。
5. **打包验收**：完成宿主协议、前端、运行文件清单、构建与相关回归测试后重新构建安装器；修改源码不会更新原有 EXE。

目前没有进行火山真实调用、微信原生发送、唱歌模型部署或安装器构建。离线编码测试通过不代表微信已支持发送语音。
