# 原曲人声与 AI 编排翻唱

当前源码统一使用：**原曲人声 → AI 分析编排 → 所选 RVC 音色换声 → 混入伴奏**。直接点歌、微信视频、成功解析的抖音分享和页面试听都走这条流程，最长 30 秒。语音回复继续使用 TTS → RVC，不受影响。

## AI 与音频程序的分工

1. 能力插件取得指定歌曲或当前聊天绑定的视频片段，Demucs 分离原曲人声和伴奏。
2. `scripts/music-reference.py` 测量分句时间、节拍估计、音高范围、力度和起音密度，不提取谱面。视频理解已有的采样画面、音轨转写和用户要求可作为额外参考；直接点歌没有歌词转写时仅依据声学测量和歌曲信息规划。
3. DSH 中的 AI 结合可用证据、人格与用户要求判断表达方向，提交 `source-vocal-arrangement-v1` 编排方案。情绪是模型的判断，声学测量本身不是情绪分类器。
4. 能力插件使用所选 `.pth` 对分离人声做 RVC 换声，执行合计变调，再应用分句音量及渐强/渐弱。伴奏来自同一歌曲或视频的分离结果，随人声同步变调，最后混音、响度校准并限幅。

保留原唱的旋律、节奏、咬字、停顿与主要唱腔。AI 编排能改变音高、力度与伴奏比例，不能通过这些参数重新生成另一种咬字、哭腔、气声或转音，也不代表训练出了一种新唱法。原唱干声作为 RVC 输入，未经换声的人声不直接混入成品；分离伴奏仍可能残留少量原唱。

## 编排协议

严格 JSON，不接收额外字段：

```json
{
  "version": "source-vocal-arrangement-v1",
  "emotion": "warm",
  "intention": "前句轻唱，后句逐渐加强，让人声更突出。",
  "pitchShift": 0,
  "accompanimentGainDb": -2,
  "phrases": [
    {"start": 0, "end": 10, "gainDb": -1, "contour": "even"},
    {"start": 10, "end": 30, "gainDb": 1, "contour": "build"}
  ]
}
```

- `emotion`：`warm`、`joyful`、`sad`、`bold`、`tender` 或 `restrained`，记录表达意图；没有独立的情绪换声开关。
- `pitchShift`：整数 ±3 半音，叠加能力页配置；合计须在 ±12 半音内。伴奏与人声使用同一变调量，时长不变。
- `accompanimentGainDb`：伴奏增益 -6～+3 dB；关闭伴奏时不会混入伴奏。
- `phrases`：1～16 段，时间相对当前片段，按序且不重叠，每段至少 0.15 秒；`gainDb` 为 ±3 dB，`contour` 为 `even`、`build` 或 `relax`。程序平滑衔接力度曲线。
- `intention`：单行、最多 240 字符。旧 `score-performance-v1` 仅用于读取历史任务，不接受为新生成方案。

## 绑定、记录与失败处理

视频参考限当前账号、聊天、视频与起点，30 分钟过期，生成后清理，不进入公共歌曲库。直接点歌自动找歌并分析；页面试听通过已配置的 DSH 模型与默认人格编排，只生成本机音频，不另填模型密钥。分离音轨按摘要核验后复用，避免重复分离。

任务目录保留 `performance.json`、原曲人声、换声结果及混音记录。`rvc/cover_result.json` 核验所选模型、输入人声摘要、实际推理和变调；最终 `result.json` 记录 `source_vocals_used:true`、`control:source-vocal`、方案摘要、实际分句力度、伴奏增益及同步变调。只有处理及校验成功才返回成品；微信送达仍以真实回执为准。

分析、模型编排、音轨摘要、换声或执行校验失败时明确失败，不静默省略 AI 编排，不返回其他音色。聊天撤销授权、账号变化或用户取消时停止提交生成。CPU 仍需执行分离和 RVC，耗时受机器与片段影响，不保证固定秒数。

安装只需 RVC/分离环境；语音回复另需 TTS。升级清理应用管理的旧演唱环境，保留历史任务与生成音频。详见 [音频环境](AUDIO_RUNTIME.md)。
