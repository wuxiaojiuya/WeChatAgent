# v0.2.15 · 微信 Hook 接入统一与旧后端清理

微信接入统一使用 **4.1.8.27 供应商 Hook** 的 API、HTTP 消息回调和项目缓存。删除旧数据库读取器、账号扫描、SQLCipher 运行依赖及旧 DLL 加载分支，安装包也同步清理。

## 连接和启动

- 在设置页选择微信程序后点击“打开微信”，项目自动准备并加载内置 Hook；登录微信后，在概览页启动助手。
- 接收服务改为独立 Hook 回调接收器，使用新的连接状态和运行状态接口。联系人、群列表、群成员及媒体获取走供应商 API。
- 不扫描微信账号目录，不获取数据库句柄或执行 SQL，不重复比较登录账号；消息上下文和引用从项目已接收的缓存获取，不补查微信历史数据库。
- 修复供应商好友列表 `contact_list` 响应解析，按真实好友关系过滤并显示备注、昵称。

## 发送和既有能力

- 文字、原生语音、图片、文件及表情投递使用 Hook 回执；区分“接口已受理”和“服务器已确认”，未知结果不自动重发。
- 保留 MP3/SILK 语音、原生 @、引用回复、拍一拍，以及 DSH 的朋友圈、个人资料和群名工具。
- 语音、RVC 翻唱、视频理解、绘画、人格和共同记忆继续使用既有能力链路；本版重点是统一微信接入与部署，不改变唱歌引擎。

## 安装和升级

适配 **Windows x64、微信 4.1.8.27**，DSH 继续独立安装。

1. 停止助手并退出旧版 WeChatAgent，运行新版安装包升级。
2. 升级保留已有设置、密钥、人格、音色、登录凭据和项目聊天记录。旧项目程序仅归档到项目自己的维护目录，不修改微信客户端数据库。
3. 在设置页打开微信并登录，再到概览页启动助手。按提示重新加载 DSH 插件，使新接收服务和能力配置生效。

旧账号扫描、旧配置和旧操作接口已停止服务，返回 410；第三方集成应切换到当前 Hook 连接接口。已加载旧组件的微信需要完整退出后，通过项目重新打开。

## 验证范围

- Node 全量回归 1003 项通过；版本元数据、安装目录及连接迁移另有定向回归。
- 干净内置 Python 3.13.16 完成 17 套、180 项测试，覆盖 Hook 接收、供应商 API、联系人、媒体、语音、视频和运行环境。
- 安装包验证源文件摘要、Hook 组件摘要、首次部署、升级保留和空 PATH 下的内置运行环境，并拒绝旧读取器及 SQLCipher 文件进入安装资源。
- 本次发布不重启真实微信，不发送测试消息或朋友圈；未在另一台物理电脑上完成安装验收。真实平台权限及供应商接口限制仍见 [Hook 接入说明](../SUPPLIER_HOOK_41827.md)。

附件提供 Windows x64 安装包、源码 ZIP、Hook ZIP、`SHA256SUMS.txt` 和 `VERIFICATION.json`。最终文件摘要和部署检查结果以附件为准。
