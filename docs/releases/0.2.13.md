# v0.2.13 · 微信连接校验与自然称呼

本版完善微信消息数据库的可用性检查、连接故障提示与启动消息读取，并调整人格提示，使不同好友可以形成各自的昵称和相处方式。

## 微信连接

- 读取器启动及每次打开消息分库时检查真实表结构，不能仅凭微信已登录、接口端口可访问或联系人可读判断消息读取正常。
- Hook 仍列出分库、但无法读取其表结构时，明确报告 `HOOK_MESSAGE_DATABASE_UNREADABLE`；不把 SQL 失败伪装成空聊天，也不跳过失败分库。
- 连接验证、运行状态与启动日志显示具体原因和恢复步骤。正常的空消息表及没有当前聊天数据的可读分库继续正常工作。
- 旧表情记录在消息轮询后逐条迁移，减少大量账号校验对启动和收消息的阻塞。

**已失效的 Hook 数据库连接仍需由微信重新建立。** 遇到上述错误，请停止助手，从系统托盘完整退出微信，再通过项目“打开微信 4.1.8.27”启动并登录，随后连接并验证。本版完善检测与提示，没有替换供应方 DLL，不承诺消除其所有连接故障。

## 人格与称呼

- 人格中的性格作为表达倾向，根据对象与当前语境调整；去掉默认人格中固定昵称触发生气、强制反驳及硬性字数限制。
- 不同好友可以有不同的私下昵称，普通友善称呼无需修改人格卡或提交审批；群聊按实际发言人区分相处约定。
- 会话摘要保留是谁称呼谁、已接受的叫法，不将某个好友的昵称变成全局改名，不将称呼当作管理员身份或权限授权。
- 人格生成、自主调整和不同工作模式使用一致的称呼边界；升级迁移已知旧提示，保留当前会话历史。

## 安装与验证

适配微信 **4.1.8.27**，继续使用独立 DSH 与项目能力插件。安装包包含新版读取器与插件代码；升级后重新打开 WeChatAgent，按提示加载新版 DSH 插件。已有设置、密钥、自有音色和会话历史继续保留，已有用户人格卡不会被默认卡覆盖。

本机在重新打开匹配微信后，已验证绑定账号一致、5 个允许会话的真实历史可读、实时轮询持续更新、消息桥接和 DSH 均就绪。连接复核没有主动发送测试消息。本机验证不能代表所有电脑或供应方 Hook 的全部运行情况。

附件包括 Windows x64 安装包、源码 ZIP、Hook ZIP、`SHA256SUMS.txt` 与 `VERIFICATION.json`。安装验收使用临时目录检查首次部署、升级替换与用户数据保留；不停止当前服务或向微信联系人发送测试消息。
