# 微信 4.1.10.27 原生语音

用户选择 4.1.10.27 后，当前本地配置使用 `state/hook/wechat-4.1.10.27/Weixin.exe`。客户端与核心 DLL 的版本及腾讯数字签名已核验；安装包 SHA-256 为 `54203fc2b41983fa106b0af0d67f86befc56ccd3dc1005d4bab6de8ea36b4f74`，来源记录位于工作区 `installers/Weixin_4.1.10.27_x64.source.json`。

发送组件来自用户提供的“微信语音部署包(整合).zip”，核对记录见 [语音包评估](VOICE_PACKAGE_REVIEW.md)。采用其经过哈希核对的 `version.dll` 和 `WeChatVoice.dll`，没有直接执行附带 JS 补丁。现有 NT 读取器、人格、记忆、聊天 ID 和模型配置继续使用。

## 本机配置

- 文本、文件等 Hook：`hook.baseUrl = http://127.0.0.1:30001`。
- 独立语音 DLL：`hook.voiceBaseUrl = http://127.0.0.1:30002`，附带二进制固定使用该端口。
- 两个 DLL 由启动器核对哈希、复制到匹配客户端目录，使用同一台机器独立生成的 Hook token。
- 语音健康检查必须验证实际版本、PID、唯一数据库账号，并与主 Hook 及读取器一致；登录前监听服务成功不等于聊天发送就绪。
- 正常从 `Launch-Hook-WeChat.cmd` 打开匹配客户端；不要给其他版本复制本 DLL。客户端保护可通过现有保护脚本恢复。

## 使用

1. 在已打开的匹配微信中完成登录，再通过控制台设置读取连接和允许聊天。
2. 在“能力 → 语音回复”配置肥鱼 TTS 服务、声线、回复方式及聊天范围，生成试听。TTS 服务和模型仍需单独部署；原生发送 DLL 不负责生成声音。
3. 在“能力 → 唱歌”选择 RVC 模型、歌曲来源并授权聊天。已有分离/RVC/混音环境继续使用。
4. 重开 DSH 以载入更新的工具，再重启项目服务。`wechat_voice_reply` 由 AI 根据回复方式选择；`wechat_sing_song` 处理对话点歌，完成后发送到发起聊天。配置页试听始终只在本机播放。

语音发送使用内置 SILK WASM 编码器，不需要照抄部署文档中作者机器的 Python 或 VoipEngine 编码路径。单条语音不得超过 60 秒，超长内容明确失败，不静默截断。当前翻唱仍生成 10–30 秒片段。

## 发送状态和恢复

`scripts/native-voice-delivery.mjs` 使用独立持久队列，保存在 `state/voice-output/deliveries/`。发送意图、账号、目标、配置摘要、音频摘要和原有消息基线在原生提交前落盘。同一个来源任务编号只提交一次。

DLL 的 `ret:0` 只表示接受。适配层需要在同一聊天看到基线外的出站 type 34、匹配时长、合理发送时间和非零字符串服务器 ID，才返回 `sent:true`；无法唯一关联则保留未确认。该接口没有返回唯一原生消息 ID，所以同一聊天同时手工发送相同时长语音仍有相关性限制；实机验收时应避免并行手工发送语音，并核对手机播放。

HTTP 连接丢失、回执超时、进程重启均不自动重新提交；状态查询可以补查迟到回执。若前一条未确认且没有可定位的消息行，暂停该聊天后续音频提交，避免把前一条的迟到回执误当下一条。账号、接收目标、聊天授权或相关设置变化后停止待发任务。

翻唱开始时即绑定原账号、目标和配置；完成后再次核对，不会在用户切换账号或修改权限后把音频发到新账号。页面试听没有聊天目标，始终不发送。
