# 微信 4.1.8.27 Hook 接入

后端为 `supplier-http`，匹配微信 `4.1.8.27`。组件内置在 `components/supplier-hook/4.1.8.27/`，包含 DLL、加载器和 SHA256 清单。用户只需选择微信程序，不需填写 Hook 目录或 HTTP 地址。

## 接入结构

`Hook HTTP 推送 → SupplierReader 项目缓存 → HookOneBot → Bridge / DSH`

当前 supplier-http 路径不读取或修改微信数据库，不获取数据库句柄，不执行 SQL，不抓取数据库密钥。接口失败不会退回旧 Hook 或数据库读取。群成员按需读取，闲置消息分发循环不请求上游历史或登录资料。

| 功能 | 供应方接口 |
| --- | --- |
| 显式连接时读取一次自身信息 | `/api/get_profile_new` |
| 运行中联系人名称元数据 | `/api/get_frien_lists`（供应方原始拼写，不作为添加好友的列表来源） |
| 添加好友、搜索及刷新列表 | `/api/update_all_friend`（每次请求直接查询完整好友列表） |
| 群列表、群成员 | `/api/get_chatroom_list`、`/api/get_room_members` |
| 文字、群原生 @、引用、拍一拍 | `/api/send_text_msg`、`/api/send_at_text`、`/api/send_quote`、`/api/send_pat` |
| SILK、MP3 原生语音发送 | `/api/send_voice`、`/api/send_mp3_voice` |
| 图片、文件、表情发送 | `/api/send_image_msg`、`/api/send_file_msg`、`/api/send_emotion_msg` |
| 语音下载 | `/api/download_voice`，`newMsgId`、`length`、`MsgId`、`path` |
| 图片、视频、文件下载 | `/api/download_img`、`/api/download_video`、`/api/download_file`、`/api/cdn_download` |
| 文字、图片朋友圈及回复 | `/api/sns_post`、`/api/sns_send_img`、`/api/sns_comment_reply` |
| 自己的昵称、头像、签名及当前群名 | `/api/mod_self_nick_name`、`/api/upload_head_img`、`/api/mod_self_nick_signature`、`/api/mod_chatroom_topic` |

HTTP 回调固定指向本机网关 `/api/recvMsg/<随机令牌>`，TCP 关闭。私聊、群聊及自己的消息受支持，大整数消息 ID 保持字符串。`msgSource.atuserlist` 提供原生 @ 信息，不仅凭昵称猜测被 @。

## 缓存和引用

允许聊天的消息写入项目自己的 `state/hook/accounts/<连接标识>/events.json`，上限 5,000 条 / 16 MiB。这不是微信数据库。本地消息 ID、服务器 ID 和客户端 ID 分开保存。没有订阅者时保留待办，重启继续分发；已分发记录在保留窗口内去重。待分发记录不会被清理以腾出空间，满容量明确报错。

消息 HTTP 路由只返回项目缓存，不补查微信历史。项目未运行期间的消息和已淘汰附件无法恢复。引用文字可使用回调内嵌原文；引用附件及原生引用发送需要同一会话的完整原消息已被缓存，缺失时报错，不查库猜测。自己的发送回调不会触发 AI 自问自答，也不冒充最终服务器回执。

好友选择器依据关系字段排除陌生人、已删除好友及公众号。群列表文档没有响应结构，兼容明确列表、嵌套列表和群 ID 映射；未知结构明确报错。语音下载需要回调中的真实 MsgId、完整 newMsgId 和长度；字段不足时不截断消息 ID 或回退查库。

## 单账号和运行

点击连接时读取一次自身信息，只用于消息方向、项目缓存及任务归属。运行时不重复查询或比对登录账号，不要求 `X-WeChatAgent-Account`；`account_wxid` 仅供信息。组件健康检查仍核对来源、版本、监听进程和就绪状态，返回 `singleAccount:true`、`accountVerification:"not-required"`、`wechatDatabaseAccess:false`。

在设置页点击“打开微信”，程序会打开匹配微信并自动加载内置 Hook；在微信窗口完成登录后，到概览点击“启动助手”。启动时自动准备连接与消息接收服务，无需单独点击“连接并验证”。DSH 配置和允许聊天保存在项目中；首次启动后可选择允许的好友或群聊。本机网关固定为 `http://127.0.0.1:30001`，供应方为 `http://127.0.0.1:19088`。

好友列表兼容文档中的 `data` 与当前 Hook 实际返回的 `contact_list`。`friend_count` 只表示数量，不作为好友身份的依据；目录中的非好友、公众号和系统联系人仍按关系字段过滤。

`get_frien_lists` 可能返回 Hook 自己的 KV 缓存，因此添加聊天不使用该接口或项目中上一次的目录。每次打开“添加好友”、搜索或刷新好友列表，均调用 `update_all_friend` 并等待这次响应；添加群聊则直接调用 `get_chatroom_list`。没有每日同步、冷却或缓存回退，查询期间清空旧结果，失败显示错误供重试，不展示旧列表冒充最新结果。好友完整查询最长等待 120 秒；网络等待不占用消息接收的元数据锁。已允许私聊的消息接收按稳定会话 ID 授权，不以目录是否包含该好友作为接收条件。

组件运行副本位于 `%LOCALAPPDATA%/WeChatAgent/supplier-41827/<项目路径摘要>/`，摘要与内置清单一致。发送及下载文件使用英文运行路径，避免供应方 DLL 无法打开中文路径。

已审阅 DLL 忽略 HttpServerHost，固定监听 `0.0.0.0:<端口>`。仅摘要为 `0f66f21d86d8d273e6da0fb8d0fbeae59fa0a501e633504aed52f77b79c7a528` 的版本允许此行为；项目请求仍走本机 IPv4。项目网关不能替供应方接口提供网络隔离。不要公开含秘密回调路径的配置或原始日志。

## 调用和确认

OneBot 支持 `get_friend_list`、`get_group_list`、`get_group_member_list`、`get_group_member_info`。成员查询要求该群位于允许聊天。

`send_group_msg.message` 支持 `text` 和 `at`；`at.data.qq` 为映射成员数字 ID，`all` 表示所有人。多成员按逗号传递，仍需实机联调；所有人使用文档的 `notify@all`。

`reply.data.id` 为已收到消息的 rawid 或完整服务器 ID。原文、发送者、时间与来源由同会话缓存取得，不信任调用方伪造的引用字段。同条消息同时包含 @ 和引用时明确返回不支持。

`send_pat`（兼容 `send_poke` / `poke`）传会话与成员。`send_mp3_voice` 传会话、本机绝对 MP3 路径及可选毫秒时长；文件不超过 16 MiB，提供时长时限 1–60000 毫秒。原有 SILK 语音回复及翻唱发送继续可用。

新动作发送前持久记录，超时或未知响应不自动重发。通用成功码只记为 `receipt:"supplier-api"`、`delivered:"api-acknowledged"`，返回本机 `operation_id`，不编造微信消息号；带完整服务器 ID 的目标匹配原生成功回执才记为服务器确认。普通文字仍使用明确的本机 `api-text:` 标识。

图片、文件、表情的一般成功码只代表已提交；仅有 clientId 的发送回调可能无法取得最终确认，保持未确认且不自动重发。语音中间状态 `ret:-2/endFlag:1` 不是成功。最终上传确认需要 `ret=0/endFlag=2/cancelFlag=0`，以及目标、字节范围和服务器 ID 匹配。

**时长限制：** 此 DLL 按 `floor(SILK字节数 / (1.8*1024))*1000` 估算时长，曾将 30 秒翻唱标为 62 秒。项目保留实际及供应方时长，不变速破坏音频；精确显示需供应方修复。

## DSH 自主工具

已允许的微信会话向 DSH 提供发布文字朋友圈、发布图片朋友圈、回复朋友圈、修改自身昵称、头像、签名、当前群名七种动作，以及朋友圈列表、详情和操作状态查询工具。由 DSH 结合交流自主选择调用，不另加管理员审批或关键词触发。微信账号本身的群操作权限仍由微信决定。

头像和图片朋友圈使用本轮收到的图片引用或同会话已完成的绘画任务；模型不传文件路径、令牌、网关或其他群的目标。供应方图片朋友圈接口只明确支持一张图，因此当前不拼装多图参数。写操作先记录再提交，相同操作在超时、重启后保持未确认，不自动重发。

供应方 `/api/sns_post` 文档明确写有“这个发朋友圈 容易掉线 说实话不太建议用”，工具说明保留该限制。部分朋友圈查询、评论和资料修改接口没有响应结构说明；未知结构明确报错，不把空响应当作成功。未公开评论结构时不能可靠取得评论编号，不编造评论或编号。API 接受请求与最终资料已经生效分别记录。

## 同一身份的共同记忆

群聊和私聊使用同一个持续交流的 DSH 身份。开启聊天历史后，当前项目账号所有已允许且开启历史的微信会话共同提供记忆：每轮自动带入有界的跨会话近期经历与摘要，`wechat_history_search` 可检索更多旧事。原始会话、发言者、称呼关系和发送确认状态始终保留；切换会话不把他人的话当成当前人的话。

共同记忆来自项目自己的聊天档案，不读取微信数据库，也不混入无关的 DSH 编程会话、工具推理或历史附件地址。移出允许列表、关闭某会话历史或关闭全局历史后，相应来源不再参与新的检索和记忆上下文。详见 [DSH 共同记忆](SHARED_IDENTITY_MEMORY.md)。

## 验证范围

离线模拟验证列表、成员、推送、原生 @、缓存及重启去重、媒体下载、新动作网关及未知结果不重发。模拟 Hook 对数据库句柄与 SQL 路由直接报错。新增功能未逐项实机发送验证，此次没有重启微信或自动发测试消息。移除数据库访问不代表已证明客户端偶发失去收发的唯一原因。
