# 用户提供的微信 4.1.8.27 Hook

当前本机配置选择 `hook.backend: supplier-http`、精确版本 `4.1.8.27`。Hook 已内置在项目目录 `components/supplier-hook/4.1.8.27/`，包含 `libGLESv1.dll`、`x64 inject.exe`；逐文件摘要在 `files.sha256.json`。启动器固定从此目录读取并核对摘要，不依赖 installers 或用户指定目录。配置使用项目相对路径，移动整个项目后仍能定位内置组件。

准备组件时还会校验并复制到 `state/hook/supplier-4.1.8.27/`，运行副本位于 `%LOCALAPPDATA%/WeChatAgent/supplier-41827/<项目路径摘要>/`。供应方加载器从中文路径加载 DLL 存在兼容问题，因此使用独立的英文运行路径；两个副本的哈希与清单必须一致，清单不能任意指定其他 DLL 路径。运行路径和摘要记录在项目 `state/hook/supplier-4.1.8.27/manifest.json`。

匹配客户端已从版本归档下载并解压到 `state/hook/wechat-4.1.8.27/`。安装包 SHA256 为 `8a2a1d513905a5a97ca28dd5150e33bd28b75c6945e6957983a307ce274a2868`，与归档摘要一致；客户端腾讯签名有效，`Weixin.exe` 与核心 `4.1.8.27/Weixin.dll` 的文件版本均为 `4.1.8.27`。只解压到独立目录，未运行安装器或强制关闭现有微信。

## 接入结构

`用户 Hook HTTP API :19088 → SupplierReader / 本机鉴权网关 → HookOneBot → Bridge / DSH`

SupplierReader 复用项目的消息解析、权限、稳定聊天 ID 和表情管理逻辑，读取来源全部改为新 Hook 的 SQL/媒体接口。不会调用旧 DLL、抓取数据库密钥、打开旧的加密数据库，或在新接口失败时退回旧 Hook。上层语音合成、分离＋RVC＋混音、歌曲来源和缓存清理设置继续使用原有能力模块。

| 项目使用的功能 | 新 Hook 的真实上游接口 |
| --- | --- |
| 当前登录账号 | `POST /api/get_profile_new` |
| 联系人、群标题、历史、实时轮询、发送回执 | `POST /api/get_db_handle`、`POST /api/sqlite3_exec` |
| 文本发送 | `POST /api/send_text_msg`，`wxid`、`msg` |
| 原生表情发送 | `POST /api/send_emotion_msg`，`wxid`、`filepath` |
| 文件发送 | `POST /api/send_file_msg`，`wxid`、`filepath` |
| 语音回复与翻唱发送 | `POST /api/send_voice`，`toWxid`、`silkPath`；兼容字段 `wxid` 与 `toWxid` 保持相同 |
| 图片下载 | `POST /api/download_img` |
| 文件下载 | `POST /api/download_file` |
| 收到的语音 | SQL 读取 `media_*.db` 中精确消息的 SILK BLOB，经本机解码 |

项目内部保留 `/SendTextMsg` 等适配路由以复用持久发送队列；这些路由由新的 Python 网关提供，所有微信操作再转为表中的新 Hook API。它们不是旧 DLL 接口的网络调用或回退通道。

SQL 仅来自程序内置的只读语句，参数转义并使用固定字段别名；BLOB 通过 `hex(CAST(... AS BLOB))` 获取。服务器消息 ID 保留完整精度。实时轮询仅覆盖已允许聊天，启动不回放旧消息。回调只保留经账号和聊天核对的图片下载辅助信息，不直接触发 AI 回复或确认发送。

## 本机操作

1. 停止助手服务，从系统托盘完全退出现有微信。
2. 在“设置 → 连接设置”选择微信 **4.1.8.27** 对应的 `Weixin.exe`。无需填写 Hook 文件夹或 HTTP 接口地址。
3. 点击“打开微信 4.1.8.27”，由供应方启动器加载 DLL；在微信窗口登录。
4. 点击“连接并验证”。程序核对 API 监听进程、程序路径、精确版本、加载的 DLL 哈希、实时账号和数据库接口。无需数据库目录或密钥。
5. 完成 DSH 连接后启动助手，选择允许的聊天。切换到其他微信账号前先停止服务，重新连接并验证。

“准备发送组件”会备份并更新 `%APPDATA%/WechatTools/config.ini`，HTTP 回调指向项目网关 `:30001` 的随机秘密路径，关闭 TCP。真实验证确认：这份供应方 DLL 的 HTTP 启动函数固定拼接 `http://0.0.0.0:<端口>`，忽略 `HttpServerHost`；仅修改 INI 无法改变监听地址。项目调用地址仍限定为 `127.0.0.1`。仅 SHA256 为 `0f66f21d86d8d273e6da0fb8d0fbeae59fa0a501e633504aed52f77b79c7a528` 的这份 DLL 可使用通配监听，其他 DLL 仍需本机监听。通配监听意味着供应方接口也监听局域网；项目的带鉴权网关只监听本机，不为供应方接口额外提供网络隔离。启动器实际核验 DLL、监听进程及地址后才报告就绪，供应方“注入成功”日志本身不算成功。原 INI 备份在组件目录，不要公开含秘密回调路径的配置或原始日志。

真实 SQL 返回为 `{code:1,data:[...],total:N}`，空查询为 `{code:0,msg:"no data",total:0}`，适配同时支持文档的直接数组。该 DLL 对部分 SQL 错误也返回相同的 `no data`，因此连接探针要求联系人和每个消息库的计数实际存在；空结果本身不证明查询语法成功，也不能作为发送成功回执。

该 DLL 的 `sqlite_master WHERE name=...` 对部分消息表错误返回计数 0；供应方适配器为固定的表存在性查询增加 `type='table'`，无需修改共享消息解析器。媒体发送先生成按内容摘要命名的英文路径副本，避免供应方原生文件读取不兼容中文路径。

项目内部固定使用鉴权网关 `http://127.0.0.1:30001` 和供应方服务 `http://127.0.0.1:19088`，不在用户设置中提供编辑入口。准备配置及控制台保存设置时自动恢复内置路径和接口地址，旧页面提交的自定义值不会生效。端口被占用时应根据连接诊断处理占用进程，无需用户猜测或填写接口地址。

## 验证与边界

离线契约测试使用内存中的模拟 Hook 验证联系人、完整历史、Unicode/BLOB、大整数消息 ID、收到的语音、图片/文件下载、发送参数、回调与网关权限、账号变化和提交确认。原生语音队列测试覆盖新后端、语音回复/翻唱以及超时不重发。

2026-11-03 已完成本机实际账号验证：联系人和历史读取、文字服务器回执、DSH 插件模型调用、原生 5 秒语音及 30 秒 RVC DJ 翻唱发送。用户确认手机文件传输助手收到并可播放语音，翻唱人声和伴奏正常。真实发送仅限文件传输助手；图片、文件与其他联系人收发尚未逐项实测。

发送接口的 `code:1` 只代表已提交；语音 `ret:-2/endFlag:1` 是中间状态。文字仍等待精确匹配的新数据库记录和服务器消息 ID。此供应方语音上传成功后没有写入电脑端消息库和界面，手机端可正常收到，因此语音另外接受完整服务器最终响应：`ret=0/endFlag=2/cancelFlag=0`、正数完整消息号，以及匹配的发件账号、收件人、最后包偏移和总字节数。未知提交仍不自动重发。

**供应方时长元数据限制：** DLL 固定用 `floor(SILK文件字节数 / (1.8*1024))*1000` 估算时长，而非读取实际 SILK 帧；本次 30 秒翻唱被标为 62 秒。适配器验证该已知公式并同时保留真实音频时长和供应方报告值，不变速或破坏音频来凑元数据。手机端播放内容已验证；精确显示秒数需要供应方修正 DLL。不要因为电脑端缺少消息记录反复发送。

## 本机肥鱼朗读服务

本机已安装独立 CPU 环境和经 SHA256 验证的肥鱼 CosyVoice3 模型，位于 `state/maintenance/audio-capabilities/feiyu-tts/`。`scripts/feiyu-service.py` 启动本机 `127.0.0.1:9880`，服务密钥存放于其 `service-data/api_key.txt` 并已写入能力配置；不应打印或上传。中文和英文文本归一化使用校验过的本地资源，避免推理时临时联网下载。此机器用 CPU 推理，生成短语音也需等待，不能按 GPU 实时速度预期。

`scripts/manage.ps1 -Action start/restart/stop` 会管理已安装的肥鱼服务，核对实际监听 PID；虚拟环境的 Python 启动器与真实 Python 子进程通过路径、父子关系及脚本标记严格核验。没有本地肥鱼配置的其他部署不会自动安装模型或启动此服务。

图片 API 的 `MsgId` 与 `newMsgId` 不等价，需已接收并核对的回调元数据。旧图片若缺少此字段会明确报 `IMAGE_CALLBACK_METADATA_REQUIRED`，不会截断大整数猜测。文件下载可能异步完成，未达到消息声明大小前返回“下载中”；无有效 attachid 的文件不会猜测下载。

供应方文档还列出项目当前未使用的管理、好友操作、支付、朋友圈等接口，本次不会自动启用这些操作。图片发送文档存在字段差异，未将其作为未经验证的发送路径暴露。
