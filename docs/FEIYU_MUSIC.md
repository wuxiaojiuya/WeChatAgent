# 肥鱼语音与 AI 编排 RVC 翻唱

在「设置 → 语音与翻唱环境」安装所需环境，再到「能力 → 语音回复」选择音色、回复方式与情绪表达。说话先通过肥鱼 TTS 合成，再使用所选 RVC 音色换声；服务协议来自 `Esmerubphire/astrbot_plugin_feiyu_voice`。语音回复与唱歌共用同一份音色档案。

项目自动读取本机肥鱼服务生成的访问令牌，普通用户无需填写 API Key。上游默认位置为 `server/.runtime/voice-service/api_key.txt`，自定义 `data_dir` 时位于该目录的 `api_key.txt`。唱歌在本机通过分离、AI 编排、RVC 和混音处理，不调用上游的唱歌 HTTP 接口。

「保存并检测音色」检查 TTS 服务、鉴权和所选 RVC 模型，不提交生成任务；配置通过后可生成试听验证实际推理。原生语音通过内置的微信 4.1.8.27 Hook 发送，核验当前账号与进程，取得消息回执才标记 `sent:true`。页面试听不向聊天发送；对话工具按授权范围投递。详见 [原生语音接入](WECHAT_NATIVE_VOICE.md)。[语音输入](VOICE_INPUT.md) 单独描述接收与识别。

「能力 → 唱歌」使用原曲人声 → AI 分析编排 → 当前所选 RVC 音色换声 → 混入伴奏。AI 可安排整段变调、分句力度与伴奏比例，旋律、节奏、咬字与主要唱腔沿用原唱。未经换声的原唱干声不直接混入成品；伴奏与人声同步变调。完整流程见 [AI 编排翻唱](SINGING_PERFORMANCE.md)。

## 使用

1. 在「语音回复」选择音色；需要新音色时上传导出的 `.pth` 推理模型和可选的配套 `.index`，填写名称，唱歌自动沿用。
2. 选择酷狗音乐、网易云音乐、QQ 音乐或仅本地曲库，设置时长（10～30 秒）、变调及是否保留伴奏。
3. 启用唱歌并勾选聊天范围，保存后在已连接的 AI 对话中直接点歌，例如“你会唱朋友的酒 DJ 版吗”。模型结合上下文提取歌名和版本，调用唱歌工具；系统优先复用匹配的本地歌曲，否则搜索所选平台并尝试可用音源，无需用户核对搜索列表。明确指定的 DJ 版不会被普通版替代。
4. 只问“你会唱歌吗”时先自然回应并询问歌名。配置页的「本机点歌测试与歌曲导入」默认折叠；测试框支持常见点歌句式，编排需要当前 DSH 模型及项目插件运行。正式对话由 AI 理解意图，不依赖固定句式。

当前聊天工具可以启动和查询本机任务，完成后向原聊天投递微信原生语音；排队或本地生成成功不等于已经送达，未确认时不会自动重复发送。聊天工具需要本机控制台运行，自动发现安装版端口并检查项目路径与聊天权限；DSH 已运行时需重新加载项目插件。禁止联网的回合只复用本地曲库。

本地歌曲可用完整文件路径导入，支持 64 MB 以内的普通 MP3、WAV、FLAC、M4A。原文件不会被改动。

## 翻唱音质

新任务默认优先音质：Demucs 使用两次移位平均和 50% 重叠分离；RVC 前去除低频伴奏泄漏，降低索引混合至 0.15、辅音保护参数设为 0.15、音量包络设为 0.25。转换后根据原人声的活动包络平滑压低纯伴奏段的杂声，不直接混入未经换声的原唱干声；合计变调由配置与 AI 编排决定，伴奏同步处理。

混音使用浮点中间音轨、轻量人声压缩与两遍响度校准（目标 -16 LUFS，真峰值 -2.5 dBTP），成品 WAV 为 24 位，MP3 试听为 256 kbps。处理会比原来的快速参数稍慢。降低爆音和杂声不等于消除模型失真；音源分离残留、音色模型训练素材与演唱音域仍会影响听感，实际效果需要试听。旧成品不会被覆盖，重新点歌会使用新流程。

`scripts/music-cover.py --quality standard` 仅用于本机对比旧参数，默认是 `enhanced`。每个任务的 `result.json` 记录处理参数、实际峰值、削波采样数及纯伴奏区的人声杂声变化；这些是信号检测结果，不是主观音质评分。信号处理测试可用已部署的 Python 运行 `scripts/test-music-quality.py`。

三平台使用公开网页接口，不需要把登录凭据交给其他网站。接口可能变化，部分歌曲需要登录、会员或购买；没有可用音频时会明确报错，不能保证任意歌曲都能自动下载。平台只返回试听片段时，按片段实际长度处理并标注。搜索失败仍可使用本地曲库。

## 网易云账号登录

在「能力 → 唱歌 → 歌曲来源」选择「网易云音乐」，下方会显示「网易云登录凭证（Cookie）」。在浏览器登录 `https://music.163.com`，按 F12 打开开发者工具，在 Network（网络）中刷新网页，选择发往 `music.163.com` 的请求，复制 Request Headers（请求标头）中 Cookie 的完整值，不包含 `Cookie:` 前缀，粘贴到本机配置页。

点击「保存并验证网易云登录」会保存凭证并请求网易云账号接口，确认是否仍处于登录状态；验证不生成音频，也不发送微信消息。会员账号不保证每首歌曲均有可用音源，仍以平台实际返回的权限、音频地址及试听标记为准。

凭证只保存在本机 `state/voice-output/capabilities.json` 中，不回显、不交给模型，不随源码或安装包分发。输入框留空保留已有凭证，勾选清除后保存可删除；切换其他来源会隐藏输入区并保留已有凭证。仅当前来源为网易云时使用该凭证，不发送给其他音乐平台或音频下载 CDN。凭证失效时，请重新登录并更新，不要通过聊天发送 Cookie。

## 自动清理

- 在线下载的歌曲保存在 `state/music-library/`，下载后 7 天到期，运行时每小时检查，启动、搜索及查看状态时也检查。
- 翻唱任务运行期间暂缓清理，避免正在使用的歌曲被删除。
- 手动导入的歌曲和上传的 RVC 模型不参与自动删除。
- 控制台关闭期间不会后台运行清理程序；下次启动时清理已过期的下载缓存。

## 本地文件与运行环境

- `state/rvc-models/`：上传的推理模型与索引。模型通过 `torch.load(weights_only=True)` 验证；不接受需要执行 pickle 代码的权重文件。索引需要与模型特征维度一致。
- `state/music-jobs/`：试听成品、处理记录和中间音轨。下载歌曲的 7 天规则只针对 `music-library` 中的在线歌曲缓存；试听成品保留。
- 当前 Windows CPU 运行环境位于 `state/maintenance/audio-capabilities/feiyu-cover/`，包括独立 Python、分离模型、ContentVec、RMVPE、Applio 和固定版本的肥鱼适配器。环境不随源码分发，缺少时页面会显示未准备。
- 上传的 RVC 模型使用同一运行时推理；索引可选。不同训练素材和模型可能产生不同音质，需要实际试听。

本地控制台接口均要求 `X-Console-Token`。JSON 接口前缀为 `/api/audio-capabilities/music`：`POST /request`（一句话点歌或结构化歌名、版本）、`POST /search`、`POST /cache`、`POST /import`、`POST /jobs`、`GET /jobs/:id`、`POST /preview`；模型使用 `GET /models`、`POST /models/upload?kind=pth|index&name=...`（二进制文件体）、`POST /models`（提交上传编号）。对话模型注册 `wechat_sing_song` 和 `wechat_singing_status`，按已启用的聊天范围动态开放；同一回合重复启动会复用首次任务，状态查询仅限当前绑定发起的任务。
