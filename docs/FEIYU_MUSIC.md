# 肥鱼语音与本地 RVC 翻唱

“能力 → 语音回复”配置肥鱼 HTTP 服务地址、私有 API Key、可爱 / 温柔声线和回复方式。服务协议来自 `Esmerubphire/astrbot_plugin_feiyu_voice`：提交 `/v1/speech`，轮询任务后下载 WAV。需要单独运行该服务并准备 TTS 模型。旧火山服务的密钥不会迁移到新服务。

肥鱼服务 API Key 是服务自身的访问令牌，不需要购买火山 API。上游首次启动默认生成 `server/.runtime/voice-service/api_key.txt`；自定义 `data_dir` 时位于该目录的 `api_key.txt`，也可用 `FEIYU_API_KEY` 显式设置。应使用正在连接的服务对应的令牌。本机分离＋RVC＋混音不经过这个 HTTP 服务，不需要填写此 Key。

语音配置页的“保存并检测服务”分别检查 `/health`、鉴权和 `/v1/capabilities` 中的 TTS / 所选声线配置，不提交生成任务。配置通过仍需生成试听验证实际推理。现已接入用户提供的 4.1.10.27 专用 WeChatVoice.dll：音频转 SILK 后调用本机 30002 端口的 `/SendVoiceMsg`，检测结果的 `nativeVoiceSend` 来自账号与进程核验。页面试听不向聊天发送；对话工具按授权范围发送，取得服务器消息回执才标记 `sent:true`。详见 [原生语音接入](WECHAT_NATIVE_VOICE.md)。`docs/VOICE_INPUT.md` 仍只描述语音输入。

“能力 → 唱歌”使用本机已经验证的 Demucs 分离 → 肥鱼项目的固定 Applio RVC 运行时 → FFmpeg 混音。它独立于说话音色；默认使用肥鱼 RVC，也可以上传自己的模型。微信发送仍未接通。

## 使用

1. 选择 RVC 音色；需要新音色时上传导出的 `.pth` 推理模型和可选的配套 `.index`，填写名称。
2. 选择酷狗音乐、网易云音乐、QQ 音乐或仅本地曲库，设置时长（10～30 秒）、变调及是否保留伴奏。
3. 启用唱歌并勾选聊天范围，保存后在已连接的 AI 对话中直接点歌，例如“你会唱朋友的酒 DJ 版吗”。模型结合上下文提取歌名和版本，调用唱歌工具；系统优先复用匹配的本地歌曲，否则搜索所选平台并尝试可用音源，无需用户核对搜索列表。明确指定的 DJ 版不会被普通版替代。
4. 只问“你会唱歌吗”时先自然回应并询问歌名。配置页的“本机点歌测试与歌曲导入”默认折叠；测试框支持常见点歌句式，不依赖模型账号。正式对话由 AI 理解意图，不依赖固定句式。

当前聊天工具可以启动和查询本机任务，音频在配置页试听；尚未接入微信音频发送和生成完成后的主动投递，不能将排队、生成成功描述为已经送达。聊天工具需要本机控制台运行（默认 3210 端口，可由 `WECHATAGENT_CONSOLE_PORT` 指定），并检查项目路径与聊天权限；DSH 已运行时需重新加载项目插件。禁止联网的回合只复用本地曲库。

本地歌曲可用完整文件路径导入，支持 64 MB 以内的普通 MP3、WAV、FLAC、M4A。原文件不会被改动。

## 翻唱音质

新任务默认优先音质：Demucs 使用两次移位平均和 50% 重叠分离；RVC 前去除低频伴奏泄漏，降低索引混合至 0.15、辅音保护参数设为 0.15、音量包络设为 0.25。转换后根据原人声的活动包络平滑压低纯伴奏段的杂声，不混入原唱、不自动改变调高。

混音使用浮点中间音轨、轻量人声压缩与两遍响度校准（目标 -16 LUFS，真峰值 -2.5 dBTP），成品 WAV 为 24 位，MP3 试听为 256 kbps。处理会比原来的快速参数稍慢。降低爆音和杂声不等于消除模型失真；音源分离残留、音色模型训练素材与演唱音域仍会影响听感，实际效果需要试听。旧成品不会被覆盖，重新点歌会使用新流程。

`scripts/music-cover.py --quality standard` 仅用于本机对比旧参数，默认是 `enhanced`。每个任务的 `result.json` 记录处理参数、实际峰值、削波采样数及纯伴奏区的人声杂声变化；这些是信号检测结果，不是主观音质评分。信号处理测试可用已部署的 Python 运行 `scripts/test-music-quality.py`。

三平台使用公开网页接口，不需要把登录凭据交给其他网站。接口可能变化，部分歌曲需要登录、会员或购买；没有可用音频时会明确报错，不能保证任意歌曲都能自动下载。平台只返回试听片段时，按片段实际长度处理并标注。搜索失败仍可使用本地曲库。

## 自动清理

- 在线下载的歌曲保存在 `state/music-library/`，下载后 7 天到期，运行时每小时检查，启动、搜索及查看状态时也检查。
- 翻唱任务运行期间暂缓清理，避免正在使用的歌曲被删除。
- 手动导入的歌曲和上传的 RVC 模型不参与自动删除。
- 控制台关闭期间不会后台运行清理程序；下次启动时清理已过期的下载缓存。

## 本地文件与运行环境

- `state/rvc-models/`：上传的推理模型与索引。模型通过 `torch.load(weights_only=True)` 验证；不接受需要执行 pickle 代码的权重文件。索引需要与模型特征维度一致。
- `state/music-jobs/`：试听成品、处理记录和中间音轨。下载歌曲的 7 天规则只针对 `music-library` 中的在线歌曲缓存；试听成品保留。
- 当前 Windows CPU 运行环境位于 `state/maintenance/audio-capabilities/feiyu-cover/`，包括独立 Python、分离模型、ContentVec、RMVPE、Applio 和固定版本的肥鱼适配器。环境不随源码分发，缺少时页面会显示未准备。
- 上传的 RVC 模型使用同一运行时推理；索引可选。不同训练素材和模型可能产生不同音质，需要实际试听。

本地控制台接口均要求 `X-Console-Token`。JSON 接口前缀为 `/api/audio-capabilities/music`：`POST /request`（一句话点歌或结构化歌名、版本）、`POST /search`、`POST /cache`、`POST /import`、`POST /jobs`、`GET /jobs/:id`、`POST /preview`；模型使用 `GET /models`、`POST /models/upload?kind=pth|index&name=...`（二进制文件体）、`POST /models`（提交上传编号）。对话模型注册 `wechat_sing_song` 和 `wechat_singing_status`，按已启用的聊天范围动态开放；同一回合重复启动会复用首次任务，状态查询仅限当前绑定发起的任务。
