# AI 人格申请与管理员审批

1. 在「聊天 → 添加好友」中勾选好友，再勾选「设为管理员」，保存聊天范围并应用配置。已有好友可在「会话设置 → 基本设置」中设置管理员。
2. 管理员必须是真实好友，且在允许的好友聊天范围内。文件传输助手、公众号、当前登录账号不能充当审批人。名单与助手模式的管理员共用，可在设置中统一管理。
3. 配置管理员后，AI 可以根据对话拟定自己的完整人格卡。也可以对它说：「根据我们的聊天，为自己设定人格并申请管理员同意。」模型只能提交提案，不能直接写入人格或批准自己的申请。
4. 管理员收到微信私聊，包含申请会话、修改理由、人格全文和审批编号。长内容分条发送，全文确认送达后才接受审批。
5. 管理员在该私聊中单独回复通知里的完整指令，例如 `同意人格 abcdef123456` 或 `拒绝人格 abcdef123456`。不接受群聊、引用消息、语音转写、昵称声明或缺少编号的「同意」。
6. 第一位合格管理员的决定生效。同意后创建独立人格卡并绑定到申请会话，下一轮对话自动使用新卡；其他聊天、默认人格和工具权限不变。拒绝则保留原人格。

「人格卡 → AI 人格申请」可查看草案与处理状态。提案会持久保存，24 小时未处理自动失效。同一会话同时只保留一条待审批申请。

审批前会重新核验登录账号、真实发送者、管理员名单、聊天范围、原人格内容、绑定与工作模式。原人格已经改动、管理员撤权或账号切换时，旧申请不能继续应用。配置修改前保存到 `state/console-backups`；生成的卡位于 `roles/AI人格-<编号>.md`。

## 本机接口

所有接口均使用控制台现有鉴权与本机地址限制。

| 接口 | 用途 |
| --- | --- |
| `GET /api/chat-administrator?key=...` | 核验好友真实身份与管理员状态 |
| `POST /api/chat-settings` | 顶层 `administrator` 开关，只能修改当前真实好友的管理员状态 |
| `POST /api/persona-proposals/propose` | 当前会话提交人格全文与理由，同时核验账号范围 |
| `GET /api/persona-proposals` | 当前账号的申请记录 |
| `GET /api/persona-proposals/notifications` | 消息桥接获取待送达管理员通知 |
| `POST /api/persona-proposals/ack` | 收到微信发送回执后确认通知送达 |
| `POST /api/persona-proposals/decide` | 消息桥接提交可信私聊消息与账号范围，程序核验审批 |

模型仅获得 `wechat_propose_persona`、`wechat_persona_proposal_status` 两个绑定当前会话的工具；没有审批、任意文件写入或修改管理员的工具。

验证命令：`npm run test:persona-approvals`。
