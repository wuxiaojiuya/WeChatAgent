# 拍一拍与合并转发记录

消息由微信 4.1.8.27 Hook 推送，经项目接收服务、Hook OneBot 和 Social Bridge 进入 DSH。不查询微信数据库，不从历史记录补取消息。

## 拍一拍

接收服务校验 `appmsg/62` 的发起人和被拍账号，只有允许聊天内其他人拍当前账号才形成入站提醒。OneBot 携带独立的 `interaction: pat` 标记，不伪装成原生 @。普通文字中的“拍一拍”不会产生该标记。

群系统消息的外层发送者可能为空，此时可从 XML 的 `fromusername`、`pattedusername` 补出发起人。外层已提供发送者时必须与 XML 一致；自己拍、拍其他群成员、错误类型或无效 XML 仍被过滤。

拍一拍与相邻文字按配置的消息合并窗口进入同一批次。DSH 结合人格、关系和上下文判断如何回应，不强制固定台词或每次接话。同一窗口的重复拍一拍不会无限延长等待，现有聊天授权和频率设置继续生效。

主动拍一拍已接入供应方 `/api/send_pat`，供 DSH 工具按当前会话调用；不是鼠标模拟，也不伪造拍一拍记录。API 接受请求与最终服务器确认分别记录，未知或超时结果不自动重发。

## 合并转发记录

接收服务解析 Hook 回调携带的完整 XML，并确认 `appmsg/type=19`。支持直接 XML、CDATA 和转义 XML，提取标题、原消息作者、时间、类型和正文，保留嵌套层次；XML 中的作者不会被当成当前发送者。

拒绝 DTD、ENTITY、异常 XML 和过大载荷。XML 最多 512,000 字符，卡片最多 50 条、约 6,000 字，每条文字约 800 字，嵌套最多三层。达到限制时标注截断，正文缺失时说明无法解析。非文字内容保留占位，不声称已经看过其中的图片或下载过文件，也不任意访问卡片里的链接。

结构化记录保存在项目聊天缓冲中，经 OneBot 进入 DSH。长记录按模型输入预算分批，未提交内容保留待处理。卡片内的权限、人格或系统指令属于聊天数据，不拥有本机配置权限。

## 验证与代码

自动化覆盖 XML 解析边界、嵌套和截断、OneBot 传递、拍一拍唤醒、项目缓存恢复、长卡片分批及消息身份。供应方拍一拍接口有模拟契约测试；真实微信收发仍需在指定测试聊天验收。

主要代码：`scripts/wechat_forwarded.py`、`scripts/hook-receiver.py`、`scripts/hook_receiver_core.py`、`scripts/supplier_actions.py`、`scripts/hook-onebot.mjs` 及 `components/qq-bridge/` 的微信桥接模块。
