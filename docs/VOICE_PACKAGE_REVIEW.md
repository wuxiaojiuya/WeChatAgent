# 用户提供的语音包核对

后续状态：用户已选择 4.1.10.27，匹配客户端及语音组件现已准备并验证接口启动，见 [原生语音接入](WECHAT_NATIVE_VOICE.md)。下文记录最初的静态核对阶段。

核对日期：2026-11-02。根据用户最新要求，停止新 Hook 整体替换，改为评估下面两个本地包。本次只解压、静态读取和比较文件，没有应用补丁、安装 DLL、更改微信配置或发送消息。

## 结论

`语音插件(适配0.4.1+).zip` 是语音输入/识别插件；`微信语音部署包(整合).zip` 包含原生语音输出的 C++ 源码、DLL、JS 补丁和部署说明。后者可以作为现有项目增加语音发送的基础，但不是当前机器直接导入即用的能力包。

| 包 | 实际能力 | 当前项目的情况 |
| --- | --- | --- |
| 语音插件 | 读取当前收到的语音，上传至配置的识别 API，将转写交给原聊天模型 | 插件 ID 为 `speech-recognition`，版本 1.2.0；入口、manifest、识别逻辑、诊断逻辑与 README 的 SHA-256 均与项目 `optional-extensions/speech-recognition` 对应文件相同。项目已有 `voice-input-v1` 宿主契约。源码存在不代表已经启用或完成服务配置。 |
| 微信语音部署包 | 合成或读取 SILK，调用微信进程内的发送逻辑，生成 type 34 原生语音消息 | 明确仅适配微信 **4.1.10.27 x64**；当前项目配置为 **4.1.15.13**。当前适配器没有该发送分支。不能跨版本直接覆盖 DLL。 |

## 输出包中实际存在的发送链路

包内 `version.dll` 从同目录加载 `WeChatVoice.dll` 并调用 `WeChatVoice_Start`。语音 DLL 实现：

- `GET http://127.0.0.1:30002/health`：返回实际核心版本、进程 PID、数据库账号集合和 ready。
- `POST http://127.0.0.1:30002/SendVoiceMsg`：接收 `{wxidorgid, path, duration}`；`path` 是本机 SILK 路径，`duration` 单位为毫秒。
- 请求需要本机 Bearer token；发送还校验 `X-WeChatAgent-Account`、单一数据库账号、核心版本和发送器状态。
- C++ 代码构造 type 34 语音消息并调用微信内部发送函数，具有实际原生发送实现，不只是把 MP3 作为附件发出。
- `ret:0` 表示原生调用接受。仍需通过读取器确认新的出站 type 34 消息及非零服务器 ID，才能标记发送成功。

上述结论来自静态源码和二进制字符串核对，尚未在本机微信上运行验证，不能据此保证手机端接收和播放效果。

## 不能照抄部署的地方

1. **版本不同。** 不能只把 `expectedVersion` 改成 4.1.10.27；实际微信核心也必须是匹配版本。此前下载的 4.1.15.13 安装包不适用于这份语音 DLL。
2. **补丁针对不同的 JS 结构。** 静态复核其 7 个锚点，当前缺少 `IMAGE_EXT`、`imageMarker` 和 `sendImage` 三个锚点，应按当前源码编写接入，不能整文件覆盖。补丁插入的 TTS 分支还使用 `spawn`，但补丁本身没有补入该导入，当前文件也没有这个导入。
3. **发送记录需要改写。** 补丁在调用发送接口后才保存 accepted，且重放只跳过 confirmed。接口已提交但回执超时、进程退出或重试时可能再次提交。应先持久化发送意图；无法确定结果的任务只核对回执，不自动重发。
4. **健康检查需要更严格。** 补丁只检查 ready 和可缺省的版本字段，没有把语音服务 PID、数据库账号与当前 Hook/读取器绑定核对；接入时应补齐这些检查。
5. **端口说明不完全准确。** 文档/JS 推导“Hook 端口 + 1”，但附带 `WeChatVoice.cpp` 实际固定监听 `127.0.0.1:30002`。改变 Hook 端口不会使这个二进制自动改变语音端口。
6. **脚本与目录仍需整理。** TTS 脚本在长文档代码块内，未作为独立脚本随部署子包交付。示例包含作者机器的 Python、VoipEngine 路径；C++ 也从客户端目录向上推导项目根目录，不能直接套用当前微信安装位置。

## 与已做的语音、唱歌能力如何衔接

这里可以只采用原生发送部分：现有语音合成 / 分离 + RVC + 混音 → 已有音频转换组件生成 SILK → 原生语音发送 → 读取器确认回执。

无需为了发送语音改回文档的 edge-tts 音色，也不需要用它替换现有翻唱模型或歌曲来源。30 秒翻唱可进入同一音频发送链路；具体的微信语音时长限制需在接入时统一校验。

若采用包内现成 DLL，需要部署匹配的 4.1.10.27 客户端，并适配当前启动器、语音发送队列、聊天授权与能力页面状态。若继续使用 4.1.15.13，则需要为该版本重新完成原生语音函数和对象布局适配，不能只改版本字符串。

解压资料保存在 `state/maintenance/voice-package-review/`，没有放进正式插件目录或微信安装目录。
