# 新版 4.x Hook 整体替换评估

最新状态（2026-11-02）：用户重新指定整体迁移到其提供的 **4.1.8.27 HTTP Hook**。接入代码、启动配置和页面已改为新后端，操作步骤与实测边界见 [4.1.8.27 接入说明](SUPPLIER_HOOK_41827.md)。下文保留迁移前的文档评估，不代表当前运行状态。

核对日期：2026-11-02。用户要求整套替换现有微信 Hook，而非只接入语音接口。本次为文档与现有源码的对照评估，未切换运行后端、安装 Hook 或向任何联系人发送消息。

来源：[新版 4.x Hook 文档](https://s.apifox.cn/1d27f9da-72ec-4981-ae95-deb20a0c1412/410194170e0)。已下载并核对 26 个相关接口页；原始 Markdown 位于本机 `state/maintenance/new-hook-review/`。

## 结论

文档层面具备重做微信接入层的主要接口，可以作为整体替换候选。它与当前 WeChatAgent Hook 的协议不兼容，需要重写发送适配、消息回调、账号识别、媒体读取及启动配置。不能通过替换一个 DLL 或修改端口完成，也不能仅凭文档承诺现有功能全部无损可用。

精确微信版本、Hook 程序、回调配置方式及实际响应仍缺少验证。本机未发现文档示例端口 19088 的监听服务；本次没有实际调用其登录、下载或发送 API。

## 重要文档差异

1. `/api/send_voice` 参数是 `toWxid`、`silkPath`；MP3 接口是 `wxid`、`mp3Path`。文件路径属于 Hook 运行机器。参数名称不能统一猜测。
2. SILK 页两个响应都被标成“成功示例”。一个是 `baseResponse.ret:-2`、`msgId:0`、`endFlag:1`；另一个是 `ret:0`、非零 `msgId`、`endFlag:2`。前者不能直接确认送达；需供应方解释状态、最终响应的关联方式，并实际核对发送记录。后者说明文档存在完整结束响应的设计，仍不等于本机验收通过。
3. 普通文字发送返回示例为 `code:1,data:null,msg:success`。自己发送文字的回调只有目标、正文、时间和 `clientMsgId`，没有最终 `newMsgId`；不能把这类回调当作当前项目要求的最终服务器回执。
4. 入站回调有 `newMsgId`、`msgType`、`fromUserName.String`、`toUserName.String`；群聊另有 `member_info`、`real_content`。必须区分 `messageType` 的回调分类与 `msgType` 的微信消息类型，并将大整数服务器 ID 保持为字符串。
5. 回调被放在 OpenAPI 的 PUT/响应示例中，路径为中文描述。文档未提供明确的回调 URL 注册、鉴权、重试、ACK 和断线补发约定；不能把这些描述直接当成已确认的真实回调路由。
6. 图片发送 Schema 要求 `image_path`，示例却使用 `filepath` 并填写 Data URL。必须用实际版本验证有效字段与输入格式。
7. SQL 页明确写了二进制字段会忽略。历史正文、压缩消息及媒体可能涉及 BLOB；需实测 `hex(...)` 等只读查询能否取回原始字节，或使用对应媒体下载接口，不能默认历史/附件读取等价。
8. 登录状态、群列表、MP3 发送、语音下载等页缺少完整响应示例。多数相关页标注 `developing`，这只是文档状态，不能据此断言程序未实现或已经稳定实现。
9. 所核对的公开接口页没有声明鉴权方案，也未列出 Hook 的精确适配微信版本、启动器、下载链接及版本查询契约。需要从实际程序或供应方说明确认。

## 整体替换范围

当前系统是 `NT 读取器 → HookOneBot → Bridge/DSH`，发送端另调用本项目的 `/WeChatAgent/health`、`/SendTextMsg` 等接口。读取器同时提供历史、账号、SSE 事件、图片/文件/语音引用、表情池与群绑定服务。新 Hook 的 HTTP 路由不能直接替代这套上层约定。

建议的最终结构为 `新 Hook → 新微信接入服务（回调、查询、媒体、发送）→ 现有 Bridge/DSH`。整体替换后，旧原生 DLL 不再加载，实时收发改走新 Hook；人格、模型、记忆、唱歌生成等上层功能继续使用项目自身实现。

必须同步处理：

- 启动/停止、客户端版本选择、连接设置、账号状态与运行诊断。
- 回调入口、好友/群稳定 ID 映射、群成员身份、撤权后的丢弃与防自回复。
- 历史补读、离线缺口处理、媒体引用与下载，以及表情池兼容。
- 文字/图片/文件/语音的独立持久发送队列、限流、提交前记录及最终确认；不确定提交不可自动重发。
- 原聊天 ID、白名单、人格绑定、记忆与插件数据映射；已有待发送任务不能直接迁移后重新提交。
- 语音合成/翻唱输出转换为 SILK，接入聊天发送；AI 选择语音的工具与回复策略需要同一链路支持。

完整替换读取层的前提是历史、媒体和回执验收通过。如果临时保留旧读取器以补齐缺口，只能叫过渡接入，不能宣称已完成用户要求的整体替换。

## 开始部署前仍需的信息

- 对应 Hook 程序或源码的实际下载地址/本地完整路径。
- 供应方声明的精确微信版本与启动方式；不能由“4.x”推断为当前下载的 4.1.15.13。
- 回调配置入口、实际请求方式和代表性原始样例，特别是语音、群消息与自己发送的最终状态。

最小验收应包括账号与版本核对、私聊/群聊文字收发、原生语音条手机收听、文件/图片读取、断线恢复不漏不重、发送超时不重复，以及旧聊天配置与记忆保持关联。测试发送的接收人需由用户指定，文档示例 wxid 不是发送授权。
